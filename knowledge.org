#+TITLE: Allwinner T113-S MIPI DSI Display — Knowledge Base
#+DATE: 2026-03-18

* 1. Hardware Architecture

** 1.1 Display Pipeline

#+begin_example
RAM (Framebuffer)
      ↓
Display Engine 2.0 (DE2) — layer compositing (399 MHz)
      ↓
TCON LCD0 — video timing, CPU/trigger interface
      ↓
DSI Host Controller — MIPI DSI packet engine
      ↓
D-PHY — 4 HS data lanes + 1 clock lane
      ↓
Panel (ILI9881C 720×1280  or  EK79007 1024×600)
#+end_example

** 1.2 Key Hardware Addresses

| Component   | Base Address | CCU Clock | CCU Bus              |
|-------------+--------------+-----------+----------------------|
| CCU         | 0x02001000   | —         | —                    |
| DE2         | 0x05000000   | 0x600     | 0x60c                |
| DE2 Mixer0  | 0x05100000   | (via DE2) | —                    |
| TCON TOP    | 0x05460000   | —         | 0xabc (DPSS_TOP)     |
| TCON LCD0   | 0x05461000   | 0xb60     | 0xb7c                |
| DSI Host    | 0x05450000   | —         | 0xb4c                |
| D-PHY       | 0x05451000   | 0xb24     | 0xb4c (shared w/DSI) |

Bus register pattern: BIT(16) = reset de-assert, BIT(0) = clock gate.

* 2. Clock Tree

** 2.1 Source PLLs

| PLL           | CCU Offset | Frequency | Purpose                  |
|---------------+------------+-----------+--------------------------|
| PLL_VIDEO0_4X | 0x040      | 1596 MHz  | Master display reference |
| PLL_VIDEO0_1X | (derived)  | 399 MHz   | DE2, TCON, DSI protocol  |
| PLL_PERIPH0   | 0x020      | 600 MHz   | D-PHY digital core       |

*** PLL_VIDEO0 (CCU 0x040) — Critical M-field quirk ⚠️

The M field is *bit 1 only*, not bits 1:0. For 1596 MHz: N=133, M=2.

| Field  | Bits | Stored value | Notes                               |
|--------+------+--------------+-------------------------------------|
| N (−1) | 15:8 | 132          | N=133, stored as N−1                |
| M (−1) | 1    | 1            | M=2, stored as M−1. *BIT 1 ONLY*   |

Readback: =freq = 24 × ((reg >> 8 & 0xff) + 1) / ((reg >> 1 & 0x1) + 1)= MHz

** 2.2 Clock Distribution

#+begin_example
PLL_VIDEO0_4X (1596 MHz) → ÷4 → PLL_VIDEO0_1X (399 MHz)
  ├── DE_CLK (0x600):        BIT(31)|0x1 → 399 MHz → DE2 mixer
  ├── TCON_LCD0_CLK (0xb60): mux=0 → 399 MHz → TCON module input
  │   └── TCON0_DCLK div=4 → 99.75 MHz (DSI timing reference, not pixel clock)
  └── TCON_TOP gate (0x05460020 BIT(16)) → DSI protocol engine

PLL_PERIPH0 (600 MHz)
  └── MIPI_DSI_CLK (0xb24): mux=1, M=4 → 150 MHz → D-PHY digital core
#+end_example

TCON_LCD0_CLK = DSI bit rate per lane = pixel_clk × bpp / lanes.
For ILI9881C: 66.528 × 24 / 4 = 399.168 Mbps ≈ 399 MHz.

⚠️ MIPI_DSI_CLK source is PLL_PERIPH0 (mux index 1), *not* PLL_VIDEO0_2X (index 0).

* 3. Display Engine 2.0 (DE2)

** 3.1 Structure

Mixer0 (base 0x05100000) sub-blocks:
- *Global* (+0x0000): enable, output size, double-buffer commit
- *Blender* (+0x1000): composites channels to output
- *UI Channel 1* (+0x3000): framebuffer layer

** 3.2 Initialization Sequence

#+begin_src c
/* Enable DE mod clock */
writel(BIT(31) | 1, CCU_BASE + 0x600);
setbits_le32(CCU_BASE + 0x60c, BIT(16) | BIT(0));

/* DE internal clocks (mixer 0) */
setbits_le32(&de_clk->rst_cfg,  BIT(0));
setbits_le32(&de_clk->gate_cfg, BIT(0));
setbits_le32(&de_clk->bus_cfg,  BIT(0));
clrbits_le32(&de_clk->sel_cfg, 1);          /* source = PLL_VIDEO0_1X */

/* Global: enable, size, double-buffer */
writel(SUNXI_DE2_MUX_GLB_CTL_EN, &de_glb->ctl);
writel(1,    &de_glb->dbuff);
writel(size, &de_glb->size);

/* Clear channels, blender, and all quirk registers (see §3.3) */
memset(channels, 0, ...);
memset(de_bld, 0, sizeof(*de_bld));
writel(0, mixer_base + 0xB0000);            /* DCSC */
writel(0, mixer_base + 0x60000);            /* SMBL */
for (u32 off = 0xF0000; off <= 0xF8000; off += 0x2000)
    writel(0, mixer_base + off);            /* VEP units */

/* Blender */
writel(BIT(8),     &de_bld->fcolor_ctl);    /* PIPE_CTL: pipe 0 enable ← see §3.3 */
writel(1,          &de_bld->route);          /* pipe 0 ← channel 1 */
writel(0,          &de_bld->premultiply);
writel(0xff000000, &de_bld->bkcolor);
writel(0x03010301, &de_bld->bld_mode[0]);
writel(size,       &de_bld->output_size);
writel(0,          &de_bld->out_ctl);

/* UI layer (channel 1) */
writel(SUNXI_DE2_UI_CFG_ATTR_EN | fmt, &ui->cfg[0].attr);
writel(size,    &ui->cfg[0].size);
writel(0,       &ui->cfg[0].coord);
writel(pitch,   &ui->cfg[0].pitch);
writel(fb_addr, &ui->cfg[0].top_laddr);
writel(size,    &ui->ovl_size);
writel(1, &de_glb->dbuff);                  /* commit */
#+end_src

** 3.3 Critical Quirks

*** PIPE_CTL naming bug (U-Boot struct)
~de_bld->fcolor_ctl~ is mislabelled in the U-Boot struct. In hardware it is *PIPE_CTL*
(blender pipe 0 control at blender offset 0x00). *Bit 8 must be set* to enable pipe 0.
Without it the blender produces no output regardless of all other settings.

*** CCSC register offsets (NCAT2/D1) ⚠️

| Channel | Unit  | Mixer Offset | Notes                            |
|---------+-------+--------------+----------------------------------|
| 0 (VI)  | CCSC0 | 0xAA050      | VI channel CSC control           |
| 1 (UI)  | FCC1  | 0xFA000      | *Base* of UI1 enhancement unit   |
| 1 (UI)  | CCSC1 | 0xFA050      | *UI1 CSC control* (not 0xFA000)  |

Many drivers use 0xFA000 for CCSC01 — this is the FCC1 base, not the CSC register.
The correct UI channel CSC control offset is *0xFA050*.

Linux =sun8i_csc.h= defines =CCSC01_D1_OFFSET = 0xFA000= for =sun20i-d1-de2-mixer-0=,
which conflicts with this finding. Resolution pending Phase 7 runtime register dump.

*** DCSC and SMBL must be disabled
On NCAT2, DCSC (base 0xB0000) and SMBL (base 0x60000) must be cleared to 0 during
init. Stale state from previous boots or Linux video playback causes colour artifacts.
DCSC uses bit 1 as its enable when SMBL is present.

*** VEP units must be cleared
Clear the five VEP unit bases (FCE 0xF0000, BWS 0xF2000, LTI 0xF4000,
PEAK 0xF6000, ASE 0xF8000) to prevent stale enhancement from affecting output.

* 4. TCON LCD0

** 4.1 Role in DSI Mode

The TCON operates in "CPU interface" mode. It generates a continuous pixel stream and
an autonomous trigger counter (TRI) fires once per frame to push data into the DSI host.
This is not software-triggered — the TCON is self-sustaining once TRI_EN is set.

** 4.2 Clock and Routing Setup

#+begin_src c
setbits_le32(CCU_BASE + 0xabc, BIT(16) | BIT(0));   /* DPSS_TOP gate + reset */
writel(BIT(31) | (0 << 24), CCU_BASE + 0xb60);       /* TCON_LCD0_CLK = PLL_VIDEO0_1X */
setbits_le32(CCU_BASE + 0xb7c, BIT(16) | BIT(0));   /* TCON bus gate + reset */
sunxi_tcon_top_setup(mixer=0, tcon=0);               /* mixer0 → TCON LCD0, DSI gate */
#+end_src

** 4.3 TCON Register Configuration

#+begin_src c
setbits_le32(&lcdc->ctrl, SUNXI_LCDC_CTRL_TCON_ENABLE);       /* bit 31 */
writel(SUNXI_LCDC_TCON0_CTRL_ENABLE |
       SUNXI_LCDC_TCON0_CTRL_IF_8080 |                        /* CPU IF mode */
       SUNXI_LCDC_TCON0_CTRL_CLK_DELAY(delay), &lcdc->tcon0_ctrl);
writel(SUNXI_LCDC_TCON0_DCLK_ENABLE | SUNXI_LCDC_TCON0_DCLK_DIV(4),
       &lcdc->tcon0_dclk);
/* ... timing registers (active size, htotal, vtotal, sync widths) ... */
writel(SUNXI_LCDC_TCON0_CPU_IF_MODE_DSI | BIT(2) | BIT(0),
       &lcdc->tcon0_cpu_intf);                                 /* TRI_FIFO_EN + TRI_EN */
#+end_src

** 4.4 Critical: CCIR CSC Disable ⚠️

Bit 19 of =TCON0_HV_IF_REG= (offset 0x58) must be *set to 1* to disable the CCIR
colour space converter. Without this, a YCbCr matrix is applied to the RGB stream
causing a strong colour shift (blue → purple/pink). Expected value: =0x00080000=.

In Linux: done in =sun4i_tcon0_mode_set_cpu()= for all DSI encoder types.

** 4.5 Critical: TRI Trigger Counter ⚠️

These three registers are *not in the U-Boot lcdc struct* (padding gap). Access via
absolute offset from TCON base. Without TRI_EN the TCON never sends frames — this
was the root cause of the original "no display" bug.

| Register | TCON Offset | Purpose                              |
|----------+-------------+--------------------------------------|
| TRI0     | 0x160       | Horizontal timing (block_space/size) |
| TRI1     | 0x164       | Block count (vdisplay lines)         |
| TRI2     | 0x168       | Start delay + trans_start            |

Calculation (mirrors Linux =sun4i_tcon0_mode_set_cpu()=):
#+begin_src c
u32 tcon_div = 4, lanes = 4, bpp = 24;
u32 block_space = htotal * bpp / (tcon_div * lanes) - hactive - 40;
u32 start_delay = (vtotal - vactive - 10 - 1) * htotal * 149
                  / (pixelclock_Hz / 1000000) / 8;     /* integer MHz division */
writel((block_space - 1) << 16 | (hactive - 1), tcon_base + 0x160); /* TRI0 */
writel(vactive - 1,                              tcon_base + 0x164); /* TRI1 */
writel((start_delay & 0xffff) << 16 | 10,        tcon_base + 0x168); /* TRI2 */
#+end_src

Verified values for ILI9881C 720×1280 @ 66.528 MHz:
#+begin_example
block_space = 840 × 24 / (4 × 4) − 720 − 40 = 500
start_delay = 29 × 840 × 149 / 66 / 8 = 6874
  (vtotal−vactive−11 = 1320−1280−11 = 29; pixelclock_MHz = 66528000/1000000 = 66)
TRI0 = 0x01f302cf,  TRI1 = 0x00d004ff,  TRI2 = 0x1ada000a
#+end_example

** 4.6 CPU Interface Register (TCON 0x60)

Expected final value: =0x10000005=
- Bits 31:28 = 0x1: DSI mode
- Bit 16: TRI_FIFO_FLUSH (pulse only; write 1 then clear, reads back 0)
- Bit 2: TRI_FIFO_EN
- Bit 0: TRI_EN

* 5. DSI Host Controller

** 5.1 Initialization Sequence

#+begin_src c
writel(SUN6I_DSI_CTL_EN, dsi + 0x000);
writel(SUN6I_DSI_BASIC_CTL0_ECC_EN | SUN6I_DSI_BASIC_CTL0_CRC_EN, dsi + 0x010);
writel(10, dsi + 0x060);  /* TRANS_START */
writel(0,  dsi + 0x078);  /* TRANS_ZERO  */
sun6i_dsi_inst_init(dsi, device);
writel(0xff, dsi + SUN6I_DSI_DEBUG_DATA_REG);

delay = sun6i_dsi_get_video_start_delay(dsi, mode);
writel(SUN6I_DSI_BASIC_CTL1_VIDEO_ST_DELAY(delay) |
       SUN6I_DSI_BASIC_CTL1_VIDEO_FILL      |
       SUN6I_DSI_BASIC_CTL1_VIDEO_PRECISION |
       SUN6I_DSI_BASIC_CTL1_VIDEO_MODE,       /* bit 0 — REQUIRED */
       dsi + 0x014);

sun6i_dsi_setup_burst(dsi, mode);
sun6i_dsi_setup_inst_loop(dsi, mode);
sun6i_dsi_setup_format(dsi, mode);
sun6i_dsi_setup_timings(dsi, mode);
#+end_src

** 5.2 Critical: BASIC_CTL1 VIDEO_MODE (bit 0) ⚠️

*If bit 0 is not set, DSI ignores TCON data entirely and only responds to LP commands.*

#+begin_example
Expected BASIC_CTL1 ≈ 0x000051f7
  Bits 15:4 = 0x51f (1311) → VIDEO_ST_DELAY
  Bit 2 = VIDEO_FILL
  Bit 1 = VIDEO_PRECISION
  Bit 0 = VIDEO_MODE  ← REQUIRED
#+end_example

VIDEO_ST_DELAY:
#+begin_src c
u16 delay = vtotal - vfp + 1;
if (delay > vtotal) delay %= vtotal;
delay = max(delay, 1);
#+end_src

** 5.3 Video Mode Enable

#+begin_src c
sun6i_dsi_start(dsi, DSI_START_HSC);   /* start HS clock */
udelay(1000);
sun6i_dsi_start(dsi, DSI_START_HSD);   /* start HS data continuous loop */
#+end_src

** 5.4 DSI Instruction Modes

| ID   | Mode   | Purpose                              |
|------+--------+--------------------------------------|
| LP11 | STOP   | LP-11 idle state                     |
| HSC  | HS     | HS clock enable                      |
| HSD  | HS     | HS data (video pixel stream)         |
| LPDT | ESCAPE | LP data transmission (DCS commands)  |
| DLY  | NOP    | Delay between HSD bursts             |

** 5.5 Working Register State

| Register      | Offset | Value      | Notes                          |
|---------------+--------+------------+--------------------------------|
| CTL           | 0x000  | 0x01010001 | DSI enabled                    |
| BASIC_CTL     | 0x00c  | 0x00000000 | Sync-pulse mode (no burst)     |
| BASIC_CTL0    | 0x010  | 0x00030001 | ECC+CRC+INST_ST running        |
| BASIC_CTL1    | 0x014  | 0x000051f7 | VIDEO_MODE + delay=1311        |
| INST_JUMP_SEL | 0x048  | 0x63f07006 | HSD continuous loop            |

INST_ST (BASIC_CTL0 bit 0) = 1 confirms the HSD loop is live.

** 5.6 DSI Bus Clock Gating Under Linux

Linux power-manages =BUS_MIPI_DSI_GATING= (CCU 0xb4c) BIT(0) off after HSD starts.
The D-PHY lane stream continues but all DSI/D-PHY register reads return 0. To read
registers on a live Linux system, temporarily re-enable BIT(0) before reading.

* 6. D-PHY

** 6.1 Clock Setup

#+begin_src c
/* PLL_PERIPH0 (mux=1) ÷ 4 = 150 MHz */
writel(BIT(31) | (1 << 24) | 3, CCU_BASE + 0xb24);  /* 0x81000003 */
#+end_src

** 6.2 IC Version Quirk (NCAT2) ⚠️

Register =0x03000024= bits [2:0] = IC version. If =ic_ver > 0=, bit 5 of D-PHY
=ANA1= (offset 0x50) *must be set* for physical layer stability.

On the test board: ic_ver = 3 → ANA1 = =0x80000020= (bit 31 | bit 5).

*Linux gap:* =phy-sun6i-mipi-dphy.c= does not implement this check. Live readback
(2026-03-14) showed ANA1 = =0x80000000= (bit 5 absent). Display operates but with
reduced signal margin. Fix needed in Linux PHY driver for Phase 7.

** 6.3 Combo PHY Register Hygiene

Stale LVDS state in =COMBO_PHY_REG1= (0x114) and =COMBO_PHY_REG2= (0x118) causes
intermittent flickering. Zero both explicitly before DSI configuration.

*Linux gap (2026-03-14):* COMBO_PHY_REG2 = =0x14= (not cleared by Linux PHY driver).
If flickering occurs under Linux, zeroing this register is the first fix to try.

** 7.1 TCON Differences

| Feature              | Linux                                      | U-Boot              |
|----------------------+--------------------------------------------+---------------------|
| Dithering (FRM)      | Writes 6 seed + 4 table regs; enables      | Not touched         |
|                      | FRM_CTL_EN if panel is 6bpc                |                     |
| ECC FIFO             | SUN4I_TCON_ECC_FIFO_EN written             | Not written         |
| SAFE_PERIOD          | NUM(3000) \vert MODE(3)                    | Not written         |
| IO_TRI               | 0xe0000000                                 | Not written         |
| CCIR CSC (HV_IF b19) | Set (disables YCbCr CSC)                   | Set (Phase 4 fix)   |

** 7.2 DSI Controller

Init sequences are functionally identical — same registers, same values, same ordering.
No meaningful difference found.

** 7.3 D-PHY Differences

| Feature              | Linux                                      | U-Boot              |
|----------------------+--------------------------------------------+---------------------|
| ANA1 bit 5 (IC-ver)  | Not set (gap, patched in Phase 5)          | Set when ic_ver > 0 |
| COMBO_PHY_REG2       | HS_STOP_DLY(20) = 0x14                     | 0x14 (aligned)      |
| Power-down sequence  | Full teardown: GCTL=0, ANA0-4=0           | No explicit teardown|

** 7.4 DE2 Mixer Differences

| Feature              | Linux                                      | U-Boot              |
|----------------------+--------------------------------------------+---------------------|
| Bulk zero 0x0-0x5FFC | Yes (loop in sun8i_mixer_bind)             | Yes (memset)        |
| VEP disable          | Enable regs at 0xA0000-0xA8000             | Zeroes 0xF0000-0xF8000 (different offsets!) |
| FCC                  | Disables at 0xAA000                        | Not touched         |
| DCSC                 | Disables at 0xB0000                        | Zeroes at 0xB0000   |
| SMBL (0x60000)       | Not touched at all                         | Zeroes at 0x60000   |
| CCSC (per-layer CSC) | Enabled/configured per-layer during commit | Not used            |
| UI scaler            | sun8i_ui_scaler module                     | Not used            |
| VI scaler            | sun8i_vi_scaler module                     | Not used            |

*** VEP offset discrepancy ⚠️
U-Boot clears VEP at 0xF0000-0xF8000, Linux disables at 0xA0000-0xA8000.
These may be different blocks or NCAT2-specific remapping — needs verification.

*** CCSC stale state risk ⚠️
Linux enables CCSC per-layer during atomic commits but does not clear CCSC enable bits
during mixer bind. Stale CCSC enable bits from a previous Linux session could persist
across soft reboot and apply an unwanted color matrix.

** 7.5 Panel (ILI9881C)

Both send the same DCS command sequence. The prepare/enable flow is equivalent.

* 8. Panels

** 7.1 ILI9881C — hd50004c30 (720×1280)

| Parameter   | Value                           |
|-------------+---------------------------------|
| Resolution  | 720 × 1280                      |
| Pixel clock | 66.528 MHz                      |
| DSI lanes   | 4                               |
| DSI format  | RGB888                          |
| Mode flags  | VIDEO | VIDEO_SYNC_PULSE | LPM  |
| DSI bit rate| 399.168 Mbps/lane               |

Timing (htotal=840, vtotal=1320):

| Axis        | Active | FP | Sync | BP | Convention             |
|-------------+--------+----+------+----+------------------------|
| Horizontal  | 720    | 40 | 10   | 70 | DRM / Linux            |
| Horizontal  | 720    | 70 | 10   | 40 | display_timing / U-Boot|
| Vertical    | 1280   | 10 | 10   | 20 | DRM / Linux            |
| Vertical    | 1280   | 20 | 10   | 10 | display_timing / U-Boot|

FP/BP values are swapped between the two naming conventions. Totals (840, 1320)

Initialization:
1. Enable power supplies, assert reset (≥10 ms), release (≥10 ms)
2. Send 190 vendor-specific DCS init commands via LP/LPDT
3. =exit_sleep_mode= (0x11) — wait ≥120 ms
4. =set_display_on= (0x29)
5. Switch DSI to HS video mode (HSC → HSD)

Key fix: Page 1 register 0xCF — some sources incorrectly list as 0xBF. 0xCF is correct.

** 8.2 Correct Initialization Order

#+begin_example
1. CCU — all bus gates and resets
2. DE2 — mod clock, clear quirk registers, UI layer, blender, commit
3. TCON — bus clock, timing registers, TRI0/1/2, TRI_EN + TRI_FIFO_EN
4. TCON TOP — route mixer→TCON LCD0, enable DSI gate
5. DSI — bus clock, register config, D-PHY power on
6. Panel — init commands (LP mode via LPDT)
7. Panel — exit_sleep + display_on
8. DSI — start HSC then HSD (video mode)
#+end_example

** 8.3 Bugs Fixed

|-------------------------------------+--------------------------------------+------------------------------------------|
| PLL_VIDEO0 M-field (1 bit, not 2)   | Wrong PLL frequency                  | Special-case in =clock_set_pll3()=       |

** 9.2 panel-skip-init Behaviour

With =panel-skip-init= in DTS, on *first boot only* (guarded by static bool):
- =ili9881c_prepare()=: skips power-on, reset, init commands, exit_sleep
- =ili9881c_enable()=: skips set_display_on
- =sun6i_dsi_enable()=: skips D-PHY init and power-on

Subsequent blank/unblank cycles perform full re-initialization.

** 9.3 Confirmed Correct in Linux

- TCON CCIR CSC: disabled in =sun4i_tcon0_mode_set_cpu()= for all DSI encoders.
- DSI BASIC_CTL1 VIDEO_MODE: set unconditionally in =sun6i_dsi_enable()=.
- Panel timing: identical 720×1280 @ 66.528 MHz.
- Panel init commands: identical sequence.

* 13. Phase 5 Learnings (initramfs / simplefb)

Preserved for reference. Strategy explored in Phase 5: U-Boot cold panel → Linux DRM
clean init → drm-splash from initramfs. Current approach (Phase 7) has U-Boot
displaying a splash and Linux inheriting the initialized panel via =panel-skip-init=.

** 13.1 simplefb Handoff

=sunxi_simplefb_setup()= (=board/sunxi/board.c=) patches the kernel DTB at =booti=
time to activate the =framebuffer-lcd0= stub. Linux =simplefb= attaches to the live
U-Boot framebuffer without hardware reconfiguration.

Required DTS stub in =chosen= node (=status= patched to "okay" at runtime):
#+begin_src dts
framebuffer-lcd0 {
    compatible = "allwinner,simple-framebuffer", "simple-framebuffer";
    allwinner,pipeline = "mixer0-lcd0";
    clocks = <&ccu CLK_BUS_DE>, <&ccu CLK_DE>,
             <&ccu CLK_BUS_TCON_LCD0>, <&ccu CLK_TCON_LCD0>,
             <&ccu CLK_MIPI_DSI>;
    status = "disabled";
};
#+end_src

⚠️ =ft_board_setup()= is only called during =booti=/=bootm=, not =run bmp-disp=.

** 13.2 CONFIG_DRM_SIMPLEDRM Conflict — Do Not Enable

With =sun4i-drm=, enabling =CONFIG_DRM_SIMPLEDRM=y= causes a NULL pointer dereference
in =of_drm_find_panel= during =sun6i_dsi_attach=. Root cause: two DRM drivers bind
simultaneously; =drm_aperture_remove_conflicting_framebuffers()= corrupts the panel
list mid-probe. Use =CONFIG_FB=y= + =CONFIG_FB_SIMPLE=y= (legacy fbdev) instead.

** 13.3 drm-splash Binary

Static ARM binary (855 KB): =drm-splash/dist/usr/bin/drm-splash=.
Opens =/dev/dri/card0=, allocates XRGB8888 dumb buffer, blits BMP/SPLR image,
calls =drmModeSetCrtc=, drops DRM master, blocks on SIGTERM.

** 13.4 Initramfs Overlay Technique

#+begin_src bash
(zcat openwrt.cpio.gz; cat overlay.cpio) | gzip -9 > combined.cpio.gz
#+end_src

Kernel processes concatenated cpio streams in order; later entries override earlier.
Embedding combined (~4.9 MB) via =CONFIG_INITRAMFS_SOURCE= produces a ~13 MB =zImage=
that fails to boot — keep initramfs external or use the FAT hook instead.

** 13.5 FAT Hook Deployment (No Kernel Rebuild)

The OpenWrt =/init= mounts =mmcblk0p4= (FAT) and =exec='s =/media/boot/init.sh= if
its MD5 matches =md5.txt=. Use to inject drm-splash without a kernel rebuild:
1. Copy =drm-splash= binary and =splash.bmp= to FAT partition.
2. Write =init.sh=: mount devtmpfs, poll =/dev/dri/card0=, launch drm-splash, exec =/sbin/init=.
3. Write =md5.txt= of =init.sh=.

Busybox =sleep= accepts integer seconds only (=sleep 0.1= fails — use counter loop).
=devtmpfs= must be mounted explicitly; OpenWrt =auot_dev= does not mount it.
