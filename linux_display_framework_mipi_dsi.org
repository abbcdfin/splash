#+TITLE: Allwinner T113-S MIPI DSI Display Clock Tree

* Root PLLs
- **PLL_VIDEO0_4X (CCU 0x040): 1596 MHz**
  - *Calculation:* 24 MHz * 133 (N) / 2 (M) = 1596 MHz.
  - *Register:* 0xF8008402 (N=133 at bits 15:8, M=2 at bit 1).
  - *Purpose:* Acts as the "Master Metronome" for the entire display aggregate throughput.
  - *Derivatives:* PLL_VIDEO0_2X (798 MHz), PLL_VIDEO0_1X (399 MHz).
- **PLL_PERIPH0 (CCU 0x020): 600 MHz**
  - Fixed high-speed source for digital module cores.

* Panel Timing & HS Link (ILI9881C)
- **Pixel Clock (PCLK): 66.528 MHz**
  - *Horiz:* 720 (Active) + 40 (HBP) + 10 (HSA) + 20 (HFP) = 790 Total
  - *Vert:* 1280 (Active) + 20 (VBP) + 10 (VSA) + 30 (VFP) = 1340 Total
  - *Refresh:* 790 * 1340 * 62.8 Hz ≈ 66.528 MHz
- **DSI HS Bit Clock: 399.168 Mbps/lane**
  - *Calculation:* (Pixel Clock * bits per pixel) / Lanes
  - *Formula:* (66.528 MHz * 24 bpp) / 4 Lanes = 399.168 Mbps
  - *Synchronization:* Generated by the D-PHY's internal PLL. It is **Frequency-Matched** to the Protocol Engine to prevent FIFO errors.

* Engine & Protocol Clocks (Processing Flow)
** 1. Display Engine 2.0 (Mixer)
   - **Source:** PLL_VIDEO0_4X (1596 MHz).
   - **Path:** PLL_VIDEO0_4X -> /4 -> 399 MHz.
   - **Register:** DE_CLK (0x600).
   - **Role:** The starting point of the pipeline. Composes the framebuffer into pixel streams.

** 2. TCON LCD0 (The "Sequencer")
   - **Source:** PLL_VIDEO0_1X (399 MHz).
   - **CCU Path:** CCU CLK_TCON_LCD0 (0xb60, mux=0, M=0, P=0) -> 399 MHz to TCON module.
   - **TCON Internal Path:** TCON receives 399 MHz -> TCON0_DCLK register (0x44, bits 6:0=4) -> 399/4 = 99.75 MHz.
   - **Purpose:** The 99.75 MHz is NOT the pixel clock! It's an internal timing reference for DSI interface.
   - **Reasoning:** Linux comment states "dclk is required to run at 1/4 the DSI per-lane bit rate."
     - DSI per-lane bit rate = 399.168 MHz
     - TCON dclk = 399.168 / 4 = 99.75 MHz
   - **Evidence:** block_space calculation in dmesg confirms tcon_div=4 (not 6).
   - **Critical:** TCON register 0x44 is TCON-internal, does NOT affect other modules or CCU clocks.

** 3. DSI Protocol Engine (The "Brain")
   - **Rate:** 399 MHz (Matching the Bit Clock 1:1).
   - **Source:** TCON_LCD0_CLK (0xb60) -> TCON_TOP Gate (0x05460020, Bit 16) -> DSI Protocol Engine.
   - **Reasoning:** On the T113-S, the DSI host is a timing slave to the TCON. The 1:1 ratio with the bit clock ensures the engine produces MIPI packets at exactly the rate the physical lanes consume them.
   - **Criticality:** Without this clock, the DSI engine cannot process DCS commands, leading to ETIMEDOUT (-110).

** 4. D-PHY Digital Core (The "Pulse")
   - **Source:** PLL_PERIPH0 (600 MHz fixed).
   - **Path:** CCU MIPI_DSI_CLK (0xb24) -> /4 (M=4) -> 150 MHz.
   - **Register Value:** 0x81000003
     - Bit 31 = 1 (gate enabled)
     - Bits 26:24 = 001 (mux=1, selects pll_periph0 from ccu-sun20i-d1.c:mipi_dsi_parents[])
     - Bits 3:0 = 0011 (M=3, divide by M+1=4)
   - **Calculation:** 600 MHz / 4 = 150 MHz
   - **Reasoning:** Clocks the digital transceiver logic of the D-PHY. It must be stable to ensure the HS state machines function correctly.
   - **Note:** NOT from pll_video0_2x! The CCU parent array has pll_periph0 at index 1.

* Understanding "Bus" vs. "Mod" Clocks
** 1. The "Bus" Clock (The Gatekeeper)
   - **Register:** CCU 0x0b4c (CLK_BUS_MIPI_DSI), Bit 0.
   - **Purpose:** Power for the AHB/APB register interface.
   - **Usage:** Enables the CPU's ability to "talk" to the module's registers. If this is off, reading/writing to the module's memory range will cause the CPU to hang.
   - **Analogy:** **The Phone Line**. Allows you to call the chip and give orders.

** 2. The "Mod" Clock (The Workhorse)
   - **Register:** TCON_TOP 0x020 (CLK_TCON_TOP_DSI), Bit 16.
   - **Purpose:** Power for the internal logic and protocol engines.
   - **Usage:** Drives functional state machines (MIPI packet generation, DCS command processing). If this is off, you can read registers, but the module will never complete a task.
   - **Analogy:** **The Employee**. The person who actually processes the orders once the phone call is received.

* Bus Infrastructure (Register Access)
- **Bus Gates:** Enables AHB/APB access to peripheral registers.
  - BUS_DE (0x60c), BUS_DPSS_TOP (0xabc), BUS_MIPI_DSI (0xb4c), BUS_TCON_LCD0 (0xb7c).
  - *Structure:* Bit 0 = Clock Gate, Bit 16 = Reset De-assertion.

* DSI Controller Register Values (Working Linux System)

** Panel Configuration (ILI9881C)
   - **mode_flags:** 0x00000c05
     - Bit 0: MIPI_DSI_MODE_VIDEO (0x001)
     - Bit 2: MIPI_DSI_MODE_VIDEO_SYNC_PULSE (0x004)
     - Bit 10: MIPI_DSI_MODE_LPM (0x400)
     - Bit 11: MIPI_DSI_MODE_EOT_PACKET (0x800)
   - **Mode:** SYNC_PULSE (non-burst video mode)
   - **Lanes:** 4

** Critical DSI Registers (After Enable)
   - **SUN6I_DSI_CTL_REG (0x000):** 0x01010001

   - **SUN6I_DSI_BASIC_CTL_REG (0x00c):** 0x00000000
     - This is CORRECT for sync pulse mode
     - Burst mode would have bits set: VIDEO_BURST | HSA_HSE_DIS | HBP_DIS
     - Sync pulse mode uses blanking packets instead, so BASIC_CTL = 0

   - **SUN6I_DSI_BASIC_CTL0_REG (0x010):** 0x00030001
     - Bit 16 (0x10000): ECC_EN - Error Correction Code enabled
     - Bit 17 (0x20000): CRC_EN - Cyclic Redundancy Check enabled
     - Bit 0 (0x00001): INST_ST - Instruction start (set by hardware during operation)

   - **SUN6I_DSI_BASIC_CTL1_REG (0x014):** 0x000051f7 ⚠️ **CRITICAL**
     - Bit 0 (0x0001): **VIDEO_MODE** - Enables video mode output
     - Bit 1 (0x0002): VIDEO_PRECISION - Precision mode for video timing
     - Bit 2 (0x0004): VIDEO_FILL - Fill mode enabled
     - Bits 15:4 (0x51f0): VIDEO_ST_DELAY(1311) - Video start delay = 1311 clocks
     - **If bit 0 is NOT set, DSI will not output video stream!**

** VIDEO_ST_DELAY Calculation
   - **Value:** 1311 clocks
   - **Calculation:** delay = sun6i_dsi_get_video_start_delay(dsi, mode)
   - **Purpose:** Delay between TCON starting and DSI video output
   - **Critical for sync:** Ensures proper timing between TCON and DSI

** Key Takeaway
   The most critical register is **BASIC_CTL1 (0x014)**.
   - **Bit 0 (VIDEO_MODE)** must be set to 1, or no video output will occur
   - This bit is written during sun6i_dsi_encoder_enable() initialization
   - Formula: BASIC_CTL1 = VIDEO_ST_DELAY(delay) | VIDEO_FILL | VIDEO_PRECISION | VIDEO_MODE
   - For working system: 0x000051f7 = (1311 << 4) | 0x7

* DE2 Blender Configuration (Base: MUX0 + 0x1000)

** Critical Registers (Verified from Linux Kernel)
   - **PIPE_CTL (0x00):** 0x00000100
     - Bit 8: PIPE_CTL_EN(0) - Enable pipe 0 (required for output!)
     - Bits 3:0: FC_EN - Fill color enable (0 = use channel data, not fill color)
     - Linux: sun8i_ui_layer_enable() sets BIT(8 + zpos)
     - U-Boot bug: Register mislabeled as "fcolor_ctl" in de_bld structure

   - **ROUTE (0x80):** 0x00000001
     - Bits 3:0: Pipe 0 source = channel 1 (UI channel with framebuffer)
     - Linux: Sets (channel << PIPE_SHIFT(zpos))

   - **ATTR[0].INSIZE (0x08):** 0x04ff02cf
     - Format: (height-1) << 16 | (width-1)
     - For 720x1280: (1279 << 16) | 719

   - **OUTSIZE (0x8c):** 0x04ff02cf (same as INSIZE for 1:1 output)

   - **BLD_MODE[0] (0x90):** 0x03010301 (standard alpha blending)

   - **OUTCTL (0xfc):** 0x00000000 (progressive) or 0x00000002 (interlaced)
     - Only bit 1 (INTERLACED) is defined

** Common Mistake
   Without PIPE_CTL bit 8 set, pipe 0 is disabled and blender produces no output, even if all other registers are correct.
